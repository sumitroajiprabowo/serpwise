# Structured data (schema.org) for Google rich results

Source: developers.google.com/search/docs/appearance/structured-data/*

## Contents
1. General policies (apply to every type)
2. Implementation & testing
3. Per-type quick reference (required / recommended / pitfalls)
4. Deprecated or limited types
5. Starter JSON-LD templates

## 1. General policies
- Format: **JSON-LD (recommended)**, Microdata, or RDFa. All are fine if valid.
- Mark up only content that is **visible to users** on that page. No hidden, irrelevant, misleading, or fake content (fake reviews are an example).
- The markup describes the page's main content and sits on the page it describes. Don't create blank pages just to hold markup. Duplicate pages carry the same markup.
- Use the most specific type. All **required** properties must be present to be eligible. A few complete and accurate recommended properties beat many sloppy ones.
- Pages with markup must not be blocked (robots.txt, noindex, login). Image URLs must be crawlable.
- Valid markup doesn't guarantee a rich result.
- A structured-data manual action removes rich-result eligibility only. It doesn't affect ranking.
- Google's documentation, not schema.org, defines what Google supports. data-vocabulary.org markup is dead.
- **Enriched results** (Job, Recipe, Event interactive search):
  - Leaf or detail pages only, never list pages.
  - Completeness is a key ranking signal.
  - Low quality across a site can exclude the whole site.

## 2. Implementation & testing
- JSON-LD can be generated by JS or Google Tag Manager. Google reads the rendered DOM.
- For Product markup, put it in the **initial HTML**. JS-generated Product markup makes Shopping crawls less frequent and less reliable.
- In GTM, read values from page variables rather than duplicating data.
- Test in development with the **Rich Results Test** (use URL mode, because code mode has CORS limits). For non-rich types use the Schema Markup Validator.
- After deploy, monitor the Search Console rich result status reports (templates break). Use URL Inspection to see the parsed markup.
- To measure impact, compare similar page groups before and after in the Performance report filtered by search appearance.
- Published case studies: Rotten Tomatoes +25% CTR, Food Network +35% visits, Nestlé +82% CTR on rich results.

## 3. Per-type quick reference
R = required, Rec = recommended.

### Article / NewsArticle / BlogPosting
- R: none.
- Rec:
  - `headline` (concise).
  - `image` (several; 16:9, 4:3, 1:1; crawlable; not a logo).
  - `datePublished`, `dateModified` (ISO 8601 with timezone).
  - `author` (Person or Organization with `name` plus `url` or `sameAs`).
- Pitfalls:
  - List each author as a separate object. Name only, with no "Posted by", job title, or publisher in the name.
  - Multi-page articles: canonical to each page or a view-all page.
  - Use Person or Organization, not Thing.

### BreadcrumbList
- R:
  - `itemListElement` with 2 or more `ListItem`s.
  - Each ListItem has `position` (1-based), `name`, and `item` (URL; optional on the last item).
- Shown on desktop.
- Reflect a typical user path, not necessarily the URL. Multiple trails are allowed.

### Carousel (ItemList host carousel)
- Only with Course, Movie, Recipe, or Restaurant.
- Two patterns:
  - Summary page: ListItems with only `position` and `url`, linking to detail pages that each carry full markup.
  - All-in-one page: ListItem `item` with full properties and `url#anchor`.
- All items must be the same type. Every item shown must be marked up. Unique same-domain URLs.

### Carousel beta (EEA, Türkiye, South Africa)
- ItemList of 3 or more LocalBusiness, Product, or Event entities on a category page.
- R per item: `image`, `name`, `url`. ListItem `position`.
- Rec: `priceRange` (under 12 chars), `servesCuisine`, `amenityFeature` (LodgingBusiness), `offers`, `aggregateRating`.

### Course list
- English only. Must be real curriculum. At least 3 courses.
- R:
  - Course: `name`, `description` (60 chars displayed).
  - ItemList: `itemListElement` with `position` and `url`.
- Rec: `provider`.
- No prices or promos in names.
- (Course *info* markup was removed from Google Search in Sept 2025.)

### Dataset
- Used by **Dataset Search only** (not Google Search since Nov 2025).
- R: `name`, `description` (50–5000 chars). DataDownload `contentUrl` if offering downloads.
- Rec: `creator`, `license`, `identifier` (DOI), `spatialCoverage`, `temporalCoverage`, `variableMeasured`, `includedInDataCatalog`, and so on.

### DiscussionForumPosting (and SocialMediaPosting)
- User-generated forum content only. Q&A sites use QAPage.
- R: `author.name`, `datePublished`, plus one of `text`, `image`, or `video`. The same fields apply to Comments.
- Rec: `author.url`, `comment` (in page order), `commentCount`, `dateModified`, `headline` (don't invent one), `interactionStatistic`, `url`, `creativeWorkStatus: "Deleted"`.
- Microdata or RDFa is preferred so long text isn't duplicated. Include the full post text.

### Education Q&A (flashcards)
- Flashcard pages, education topics. Languages: EN, PT, ES (Mexico), VI.
- R:
  - `Quiz.hasPart` with `Question`.
  - Question: `text`, `eduQuestionType: "Flashcard"`, exactly one `acceptedAnswer` with `text`.
- Rec: `about`, `educationalAlignment`, `educationalLevel`.

### EmployerAggregateRating
- User ratings of an employer that users can submit on your site.
- R: `itemReviewed` (Organization `name`, `sameAs`), `ratingValue`, `ratingCount` or `reviewCount`.
- Rec: `bestRating`, `worstRating`.

### Event
- Must be at a physical venue, public, and bookable. One event per leaf page. Not schedules or listings, not coupons or business hours, not virtual-only.
- R: `name` (event title), `startDate` (ISO 8601 with offset; date only if no time), `location` (Place with `address`).
- Rec:
  - `location.name` (the venue), `description`, `endDate`, `image` (1920px wide ideal, minimum 720).
  - `eventStatus` (EventScheduled, EventCancelled, EventPostponed, EventRescheduled with `previousStartDate`).
  - `offers` (`price`, `priceCurrency`, `availability`, `validFrom`, `url`).
  - `organizer`, `performer`.
- When cancelled, keep the dates and change only `eventStatus`.

### ImageObject (image license metadata)
- R: `contentUrl` plus one of `creator`, `creditText`, `copyrightNotice`, or `license`.
- The Licensable badge needs `license` (and ideally `acquireLicensePage`). The IPTC embedded equivalent also works, and structured data wins on conflicts.
- Mark up every page where the image appears.

### JobPosting
- Single-job detail pages. Applying must not require a login. No fee-charging postings. Expired jobs must be removed (404/410, past `validThrough`, or markup removed).
- R:
  - `title` (job title only).
  - `description` (full HTML).
  - `datePosted`.
  - `hiringOrganization` (`name`, `sameAs`, `logo`).
  - `jobLocation` (PostalAddress with `addressCountry`). Can be omitted for fully remote jobs that set `applicantLocationRequirements`.
- Rec:
  - `validThrough` (required if the job expires).
  - `employmentType` (FULL_TIME, PART_TIME, CONTRACTOR, TEMPORARY, INTERN, VOLUNTEER, PER_DIEM, OTHER).
  - `baseSalary` (MonetaryAmount; `unitText` HOUR/DAY/WEEK/MONTH/YEAR).
  - `jobLocationType: "TELECOMMUTE"` (only if 100% remote), `identifier`, `directApply`.
  - `educationRequirements`, `experienceRequirements`.
- Use the **Indexing API** for job URLs.

### LocalBusiness (and subtypes)
- R: `name`, `address` (complete PostalAddress).
- Rec:
  - `geo` (5 or more decimals), `telephone` (with country code), `url`.
  - `openingHoursSpecification`: 24h is 00:00–23:59, closed is 00:00–00:00, overnight hours go in one spec, seasonal hours use `validFrom`/`validThrough`.
  - `priceRange`, `menu`, `servesCuisine`, `department`.
  - `aggregateRating` and `review`, only if reviewing *other* businesses.
- Use the most specific subtype (Restaurant, Dentist...).

### MathSolver
- On the home page.
- R: `potentialAction` (SolveMathAction) with `target` containing `{math_expression_string}`, `mathExpression-input`, `url`, `usageInfo`, and `learningResourceType: "Math solver"`.
- Rec: `inLanguage`, `eduQuestionType`.

### Movie
- Carousel, mobile only.
- R: `name`, `image` (6:9 aspect).
- Rec: `aggregateRating`, `dateCreated`, `director`, `review`.

### Organization
- On the home or About page.
- R: none.
- Rec:
  - `name`, `alternateName`, `url`.
  - `logo` (112×112 or larger; looks right on white).
  - `sameAs` (social profiles), `address`, `telephone`, `email`, `contactPoint`, `description`, `foundingDate`.
  - Identifiers: `legalName`, `iso6523Code` (0060 DUNS, 0088 GLN, 0199 LEI), `vatID`, `taxID`.
  - Policies: `hasMerchantReturnPolicy`, `hasShippingService`, `hasMemberProgram`.
- Use `OnlineStore` for ecommerce, and LocalBusiness subtypes for physical stores.

### Product snippet (review or editorial pages; product not bought on this page)
- R: `name` plus one of `review`, `aggregateRating`, or `offers`.
- Pros and cons (`positiveNotes`, `negativeNotes`, 2 or more statements) are for editorial reviews only.
- Pitfalls:
  - Prefer `Offer` over AggregateOffer for price-drop eligibility.
  - Reviewer must be a real Person or Team name.
  - Prohibited goods are ineligible.

### Merchant listing (page where the product can be bought)
- R:
  - `name`, `image`, `offers`.
  - Offer: `price` above 0 and `priceCurrency`, or `priceSpecification`.
- Rec:
  - Offer details: `availability`, `itemCondition`, `url`, `priceValidUntil`, `validFrom`/`validThrough`.
  - Product identity: `brand.name`, GTIN (numeric), `mpn`, `sku` (ASCII, no spaces).
  - Product attributes: `color`, `size`, `material`, `pattern`, `audience`, `description`.
  - Ratings: `aggregateRating`, `review`.
  - Policies and flags: `shippingDetails` (OfferShippingDetails with `shippingRate`, `shippingDestination`, `deliveryTime`), `hasMerchantReturnPolicy`, `hasAdultConsideration`, `hasCertification`.
- Pricing:
  - Strikethrough: `priceSpecification` with `priceType: StrikethroughPrice`, never on the active price.
  - Member price: `validForMemberTier` (no `priceType`).
  - Unit price: `referenceQuantity`.
- One currency per URL. Free shipping is `value: 0`.

### ProductGroup (variants)
- R: ProductGroup `name`, `productGroupID` (or `inProductGroupWithID` on variants).
- Rec: `hasVariant`, `variesBy` (only color, size, suggestedAge, suggestedGender, material, pattern, as full schema.org URLs), `brand`, `description`, `aggregateRating`, `review`, `url` (single-page setups only).
- Each variant is a Product with a unique ID and its own preselectable URL. Multi-page setups repeat self-contained markup on each page.

### MerchantReturnPolicy
- Nested under Organization (`hasMerchantReturnPolicy`) on one policy page. Product-level overrides go under Offer.
- R: `applicableCountry` and `returnPolicyCategory` (MerchantReturnFiniteReturnWindow, MerchantReturnNotPermitted, MerchantReturnUnlimitedWindow), or alternatively `merchantReturnLink`.
- Rec:
  - `merchantReturnDays` (required for a finite window).
  - Fees: `returnFees` (FreeReturn, ReturnFeesCustomerResponsibility, ReturnShippingFees with `returnShippingFeesAmount`), `restockingFee`.
  - Process: `returnMethod`, `refundType`, `returnLabelSource`, `itemCondition`, `returnPolicySeasonalOverride`.
- Precedence: Content API, then Merchant Center or Search Console settings, then product markup, then Organization markup.

### ShippingService
- Under Organization (`hasShippingService`).
- R: `shippingConditions` (1 or more). When several match, the lowest cost wins, then the fastest.
- Rec:
  - Conditions: `shippingDestination` (DefinedRegion: `addressCountry` required; `addressRegion` for US/AU/JP; `postalCode` for AU/CA/US; not both region and postal code), `shippingRate`, `orderValue`, `weight`, `numItems`, `doesNotShip`, `seasonalOverride`.
  - Timing: `transitTime`, `handlingTime` (ServicePeriod with `duration`, `businessDays`, `cutoffTime`).
  - Service: `fulfillmentType`.

### MemberProgram (loyalty)
- Available in AU, BR, CA, FR, DE, MX, UK, US.
- R: `name`, `description`, `hasTiers` (MemberProgramTier with `name` and `hasTierBenefit`: TierBenefitLoyaltyPoints or TierBenefitLoyaltyPrice).
- Product member prices use UnitPriceSpecification `validForMemberTier`, plus `membershipPointsEarned`. Merchant Center settings win.

### ProfilePage
- The page focuses on one person or organization affiliated with the site (author page, forum profile).
- R: `mainEntity` (Person or Organization with `name` or `alternateName`).
- Rec: `dateCreated`, `dateModified` (human edits), `description`, `image` (no placeholders), `sameAs`, `identifier`, `interactionStatistic`, `agentInteractionStatistic`.

### QAPage
- One user-asked question per page, with users able to answer. **Not for FAQs** written by the site or for multi-question pages.
- R:
  - `mainEntity` Question with `name`, `answerCount`, and `acceptedAnswer` or `suggestedAnswer`.
  - Answer: `text` (full text, not an excerpt).
- Rec: `author` (plus `url`), `datePublished`, `upvoteCount`, `url` on answers (strongly recommended), `comment`, `commentCount`, `image`, `video`.
- The accepted answer must be chosen by the asker, a moderator, or votes. Unanswered questions are ineligible.

### Recipe
- R: `name`, `image` (finished dish; 16:9, 4:3, 1:1).
- Rec:
  - Descriptive: `author`, `datePublished`, `description`, `keywords` (don't repeat category or cuisine), `recipeCategory`, `recipeCuisine`.
  - Times: `prepTime` with `cookTime`, or `totalTime`.
  - Content: `recipeIngredient`, `recipeInstructions` (HowToStep or HowToSection, no "Step 1" text).
  - Nutrition and yield: `recipeYield` (required if `nutrition.calories` is set), `nutrition.calories`.
  - Extras: `aggregateRating`, `video`.

### Review / AggregateRating (review snippet)
- Supported item types: Book, Course, CreativeWorkSeason/Series, Episode, Event, Game, HowTo, LocalBusiness, MediaObject, Movie, MusicPlaylist/Recording, Organization, Product, Recipe, SoftwareApplication.
- R:
  - Review: `author` (valid name under 100 chars), `reviewRating.ratingValue`, item name.
  - AggregateRating: `ratingValue`, `ratingCount` or `reviewCount`, item name.
- Rec: `datePublished`, `bestRating`, `worstRating`.
- Rules:
  - Reviews must be visible on the page.
  - **No self-serving reviews** (a LocalBusiness or Organization rating itself).
  - **Don't aggregate ratings from other sites.**
  - Reviews must be about a specific item. No fake or undisclosed incentivized reviews.
  - Use a dot as the decimal separator.

### SoftwareApplication
- R: `name`, `offers.price` (0 if free; add `priceCurrency` if above 0), and `aggregateRating` or `review`.
- Rec: `applicationCategory` (e.g. GameApplication, BusinessApplication), `operatingSystem`.
- A pure VideoGame type is ineligible. Co-type it, e.g. `["VideoGame","MobileApplication"]`.

### Speakable (beta)
- US English news for Google Assistant.
- R: `speakable` with `cssSelector` **or** `xPath` (not both).
- Each section should take about 20–30 seconds to read. Avoid datelines, captions, and attributions.

### Paywalled content
- R: `isAccessibleForFree: false`.
- Rec: `hasPart` WebPageElement with `isAccessibleForFree: false` and `cssSelector` (`.class` selectors only).
- Apply to AMP and non-AMP versions. Googlebot must reach the full content.

### VacationRental
- Hotel Center partners only.
- R: `containsPlace` (Accommodation with `occupancy.value`), `identifier` (stable), `image` (8 or more, including bedroom, bathroom, and common area), `latitude`/`longitude` (5 or more decimals), `name`.
- Rec: `address`, `aggregateRating`, `review` (with `datePublished`), `checkinTime`, `checkoutTime`, `amenityFeature` (English values from the list), `numberOfBedrooms`, `floorSize` (unitCode MTK or FTK).

### VideoObject (+ Clip, SeekToAction, BroadcastEvent)
- R: `name`, `thumbnailUrl`, `uploadDate` (ISO 8601 with timezone).
- Rec: `description`, `contentUrl` (the file), `embedUrl` (the player), `duration` (ISO 8601), `expires`, `interactionStatistic`, `regionsAllowed` or `ineligibleRegion` (not both), `hasPart` (Clip).
- Clip:
  - R: `name`, `startOffset`, `url` (same video with a time parameter). Rec: `endOffset`.
  - The video must be 30 seconds or longer. No duplicate start times.
- SeekToAction: `target` containing `{seek_to_second_number}`, and `startOffset-input`.
- LIVE badge: `publication` BroadcastEvent with `isLiveBroadcast`, `startDate`, `endDate`. Use the Indexing API at start, end, and on changes.
- Name and description must be unique per video.

## 4. Deprecated or limited types
- **Stopped showing in Search in 2025 (docs removed Sept 2025)**: Course info, Estimated salary, Learning video, Special announcement, Vehicle listing. Claim Review was announced as phased out in June 2025.
- **Practice problems**: docs removed Jan 6, 2026.
- **FAQ**: no longer appears in Google Search from May 7, 2026 (docs removed June 15, 2026). Use QAPage only for real user Q&A.
- **HowTo**: not in Google's current search gallery. Don't promise it.
- **Dataset**: Dataset Search only.
- **Package tracking**: closed to new partners.
- **Sitelinks search box**: retired.

## 5. Starter JSON-LD templates

Organization + WebSite (home page):
```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@graph": [
    {"@type": "Organization", "@id": "https://example.com/#org",
     "name": "Example", "url": "https://example.com/",
     "logo": "https://example.com/logo-512.png",
     "sameAs": ["https://www.instagram.com/example", "https://www.linkedin.com/company/example"]},
    {"@type": "WebSite", "@id": "https://example.com/#website",
     "name": "Example", "alternateName": ["EX", "example.com"],
     "url": "https://example.com/", "publisher": {"@id": "https://example.com/#org"}}
  ]
}
</script>
```

Article:
```html
<script type="application/ld+json">
{"@context":"https://schema.org","@type":"BlogPosting",
 "headline":"How to Store Homemade Hot Sauce So It Lasts",
 "image":["https://example.com/img/hot-sauce-16x9.jpg","https://example.com/img/hot-sauce-4x3.jpg","https://example.com/img/hot-sauce-1x1.jpg"],
 "datePublished":"2026-11-01T08:00:00-05:00","dateModified":"2026-11-15T10:30:00-05:00",
 "author":[{"@type":"Person","name":"Jane Doe","url":"https://example.com/authors/jane-doe"}]}
</script>
```
